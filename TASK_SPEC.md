# TASK_SPEC — SPRINT-03b, задачи B-18…B-21

## Цель финального состояния

Последний **проверенный показанный набор** не должен исчезать при загрузке, ошибке или пустом результате и не должен получать подпись свежего снимка, если новая попытка не принесла непустой успех. Приёмка должна отдельно фиксировать то, что подтверждено тестами, локальными командами и ручной проверкой живого источника. После приёмки README должен позволять установить и запустить проект на втором ноутбуке. Это финальное состояние проекта; функции сверх задания не добавлять.

Основание: `docs/tasks/SPRINT-03b-CHANGE-REQUEST.md` (контракт B-18…B-21), `docs/tasks/SPRINT-03.md` (R3, включая уже принятые контракты преобразователя и сборщика), `docs/tasks/PROJECT_BRIEF.md` (US-01…US-10). Требования этого change request заменяют только явно изменённые правила R2 для неудачной/пустой попытки; остальные согласованные правила сохраняются.

## Исследование текущего состояния

- В `app/components/SeaMap.tsx` сейчас одно `viewState` одновременно определяет показанный набор и статус запроса. При старте загрузки `loadRealPositions` очищает суда, выбор, подпись снимка и сообщение; ошибка и исключение также очищают набор. Пустой ответ заменяет набор пустым. Это противоположно новому правилу сохранения последней картины.
- Текущая подпись источника во время загрузки становится «Загрузка…», при ошибке/без снимка — «Данных на карте нет». Сообщения об ошибке и пустом результате существуют отдельно от результата попытки. Время ошибки сейчас не берётся из `attemptedAt`; успешная подпись форматируется из `collectedAt`.
- Движение демо зависит от `viewState === "idle-demo"`: переход в `loading` останавливает его уже при нажатии. Новый контракт требует продолжать демодвижение во время ожидания и после ошибочной/пустой попытки; останавливать его следует только после непустого успеха.
- Обработка тела ответа сейчас безусловно вызывает `response.json()`. Ответ без тела попадает в catch и отображает текст ошибки подключения, а не согласованный литерал «Нет ответа сервера».
- Карта и карточка уже строятся из массива `vessels`; синхронизация маркеров удаляет отсутствующие id, а выбранная карточка вычисляется из текущего набора. Это основа для атомарной замены набора и закрытия карточки только если выбранного id нет в успешном новом наборе.
- Возврат центра/масштаба при первом непустом успехе реализован через `centeredForAisRef`; необходимо сохранить его условие и не менять вид карты при втором успехе.
- `tests/r3-browser.spec.ts` содержит старые тесты R2, явно утверждающие очистку судов/пустую подпись на ошибке и пустом ответе (тесты около строк 43–67). Это ожидаемые изменения контракта: переписать только эти два теста; тест движения и тест нейтральной иконки/карточки оставить без изменений. Новые случаи B-19 добавить в браузерные тесты с подменой `/api/snapshot` и временем только из JSON-ответов.
- `app/api/snapshot/handler.ts` уже возвращает `attemptedAt` для ошибок и `collectedAt` для успехов, в том числе для пустого успешного снимка. Для отсутствующего тела endpoint менять не требуется: клиент должен корректно обработать пустое/неразбираемое тело.
- `README.md` пока является стандартным шаблоном create-next-app и не описывает Sea Radar, настройку ключа, проверки, честный статус снимка либо ограничения. B-21 требует заменить его прикладной инструкцией.
- В репозитории есть `package.json` с командами `npm run dev`, `npm run build`, `npm run lint`, `npm test`; тестовый набор включает браузерные и node-тесты Playwright. Для B-20 фактический прогон этих команд и `npx tsc --noEmit` должен быть зарегистрирован; нельзя заранее заявлять зелёный результат.
- Статус ключа и доступность AISStream из текущего исследования не установлены; их нельзя утверждать без ручной проверки. Не читать и не раскрывать значение ключа.

## Предлагаемое решение

### B-18 — модель UI и поведение

Разделить состояние на независимые значения:

1. **Показанный набор** (суда и его подпись источника/время получения). Изначально это демо с подписью «Демонстрационные данные». Не менять этот набор и подпись при начале запроса, ошибке, отсутствии/неразбираемом ответе или пустом успешном ответе.
2. **Последняя попытка**: до первого нажатия отсутствует; при запросе — «Загрузка…»; затем одно итоговое сообщение по контракту. Во время загрузки блокировать кнопку, но не останавливать демодвижение.

Только непустой успешный ответ атомарно заменяет суда и данные подписи на AIS snapshot; результат попытки берёт время из `collectedAt`, а подпись сохраняет заданный формат, включая суффикс лимита при `truncated: true`. Этот переход прекращает демодвижение. Успех с нулём судов не является заменой показанного набора. После непустого успеха сохранить выбранный id и обновить карточку из нового набора, если id присутствует; в противном случае снять выбор. Не объединять снимки. Постоянно показывать подсказку: «После обновления страницы снова показываются демонстрационные данные».

Тексты результата попытки — буквально по change request: пустой успех с временем из `collectedAt`: `Попытка HH:MM:SS UTC: за время сбора позиции не получены`; ошибка с `attemptedAt`: `Попытка HH:MM:SS UTC: не удалось получить данные: <message>`; отсутствие пригодного тела: `Попытка: не удалось получить данные: Нет ответа сервера`; без ключа — сообщение с временем ответа и текстом `Ключ AISStream не настроен`; непустой успех — `Попытка HH:MM:SS UTC: получено судов: N`. Все времена интерфейса формировать из ответа сервера, не из часов браузера. Сохранить заданный порядок панели: кнопка, подпись источника, результат попытки, подсказка, карточка.

### B-19 — регрессионные и контрактные браузерные тесты

Подменять `GET /api/snapshot`; времена задавать литералами в ответах и проверять буквально. Покрыть все 12 сценариев списка B-19: непустой успех и остановка демо; ожидание с сохранённым набором/заблокированной кнопкой; пустая попытка после успеха; ошибка после успеха; ошибка на демо с продолжающимся движением; сохранение/снятие выбора по наличию id; неизвестные скорость/курс и нейтральный значок; `truncated`; неизменность вида карты при втором успехе; неподвижность настоящих судов при продвижении `page.clock`; пустое тело; постоянная подсказка.

Не использовать `waitForTimeout`; для движения применять `page.clock`. В отчёте перечислить изменённые прежние тесты и причину: изменяются только два R2-теста ошибки и пустого ответа из B-16; тесты движения, выбора и неизвестных полей не переписывать. Если тест выбора в проекте находится отдельно, не менять его без необходимости.

### B-20 — финальная приёмка

Выполнить и записать фактические результаты: `npm test`, `npx tsc --noEmit`, `npm run build`. Далее вручную проверить без ключа: демонстрация работает и остаётся после нажатия, результат попытки сообщает «Ключ AISStream не настроен». Проверить с ключом одной ручной успешной загрузкой с временем и количеством судов либо честно зафиксировать недоступность источника; автоматическая подмена endpoint не доказывает доступность AISStream.

Проверить, что `.env.local` не tracked (`git ls-files`), и отсутствие значения ключа в рабочей копии, `.next/static` и содержимом архива checkpoint. Не выводить и не записывать сам секрет. Каждую команду README выполнить и сверить с заявленным результатом. Не создавать checkpoint/коммит/архив в рамках B-18…B-21, если это отдельно не поручено: в разделе результата задания checkpoint 04 назван, однако запрошенное здесь ожидаемое финальное состояние и ограничение пользователя — исследование и спецификация в `TASK_SPEC.md`, без прочих действий.

### B-21 — README

Переписать шаблон в русскоязычную инструкцию для второго ноутбука: предпосылки и установка зависимостей, запуск на loopback, настройка `AISSTREAM_API_KEY` через локальный `.env.local` без значения ключа в документации, команды проверок, интерпретация snapshot/выборки, правило сохранения набора при сбое и возврат демо после обновления, ограничения и известные недоказанные обстоятельства. Описывать только команды, которые реально проверены. Обязательно указать «снимок, а не мониторинг» и неполноту выборки; не обещать «все суда района». Не добавлять альтернативные менеджеры пакетов, если они не проверяются.

## Чего не делать

- Не очищать показанный набор при нажатии, загрузке, ошибке, пустом/неразбираемом ответе; не менять его подпись на статус последней попытки.
- Не выдавать сохранённый AIS-снимок за свежий: время его получения остаётся прежним; не ставить на демо подпись AISStream.
- Не останавливать демодвижение при начале запроса, пустом ответе или ошибке; не сливать наборы; не считать отсутствие судна доказательством ухода из района.
- Не останавливать и не перемещать настоящие суда, кроме как по правилам существующего отображения; после непустого успеха они остаются снимком и не движутся.
- Не менять интеграцию AISStream, правила сбора/преобразования, контракт API без установленной необходимости; не делать несвязанный рефакторинг.
- Не добавлять автоматическое обновление, историю снимков, сравнение наборов, отметки «ушедших» судов, сохранение набора между перезагрузками, новые районы/источники/функции.
- Не менять тесты движения/выбора ради подгонки; не заменять воспроизводимый тест ручным утверждением и не считать endpoint-mock проверкой живого источника.
- Не добавлять секреты в код, README, результаты, архив или вывод команд; не создавать коммит или архив без явного отдельного решения.

## Критерии готовности

- B-18 соответствует буквальным текстам, независимым состояниям и всем правилам сохранения/замены; старый набор и подпись остаются при любой неудачной/пустой попытке, свежий результат показывается только после непустого успеха.
- Все сценарии B-19 зелёные; описаны изменённые старые тесты. Тесты движения и выбора остались без правок.
- B-20 подтверждён фактическими выводами: тесты, TypeScript, production build, ручная проверка без ключа, зафиксированный исход попытки с ключом (успех с временем/количеством или недоступность), проверка отсутствия утечки секрета.
- B-21: README содержит команды и ограничения; каждая описанная команда выполнена с указанным результатом; отсутствуют обещания мониторинга и полноты покрытия района.
- Отклонения, непроверенные пункты и статус живого источника явно отмечены, а не представлены как пройденная проверка.
