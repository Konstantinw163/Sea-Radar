# CHECKPOINT-04 — ревью B-18…B-21 / US-10

## Объём ревью

Сверены требования B-18…B-21 из `docs/tasks/SPRINT-03b-CHANGE-REQUEST.md` и US-10 из `docs/tasks/PROJECT_BRIEF.md` с реализацией `app/components/SeaMap.tsx`, браузерными тестами `tests/r3-browser.spec.ts` и `tests/snapshot.spec.ts`, инструкцией `README.md`, `package.json` и контекстом предыдущего ревью в `docs/checkpoints/CHECKPOINT-03.md`. Другие части проекта не исследовались.

Ревью включало код, документы, автоматические проверки и описанную пользователем ручную проверку живого источника. Запуск инструкции на другом ноутбуке не выполнялся. Значения секретов не читались и не выводились.

## Выполненные проверки

- `npm test` — успешно: 38 тестов пройдены (24 Chromium, 14 node).
- `npx tsc --noEmit` — успешно, ошибок нет.
- `npm run build` — успешно. Сборка сообщила, что использует окружение `.env.local`; значение переменных не проверялось и не выводилось.
- `npm run lint` — успешно.
- `git ls-files --error-unmatch .env.local` — `.env.local is not tracked`.
- `git status --short` после проверок показывает только этот неотслеживаемый файл checkpoint; прочих изменений от проверок не выявлено.

## Результаты сверки

### B-18 — состояния интерфейса R4

Подтверждено по `app/components/SeaMap.tsx`:

- Данные на карте и результат попытки ведутся отдельно (`vessels`/`displayState` и `attemptResult`). Пока ответ ожидается, набор не заменяется, кнопка блокируется, показывается «Загрузка…»; демодвижение продолжает работать (`:221-231`, `:307-312`, `:380-398`).
- Ошибка, пустой ответ и отсутствие разбираемого тела не заменяют показанный набор и подпись источника. Для ошибки/пустого результата берётся время из `attemptedAt`/`collectedAt`; для отсутствующего или неразбираемого тела выводится предписанный текст без времени (`:315-350`, `:368-373`).
- Только непустой ответ заменяет набор, обновляет подпись и время попытки, переводит отображение из демонстрационного в AIS и прекращает демодвижение. Выбор снимается, если выбранного `id` нет в новом наборе, либо остаётся и карточка читает обновлённый объект из нового набора (`:347-367`, `:233`).
- Центрирование к начальному виду делается только для первого непустого успеха; постоянная подсказка об обновлении присутствует. Порядок содержимого панели соответствует заданию: кнопка, источник, результат, подсказка, карточка (`:363-367`, `:376-398`).

### B-19 — браузерные тесты контракта R4

Проверки с подменой `/api/snapshot` находятся в `tests/r3-browser.spec.ts`; пустой ответ и ошибка без ключа дополнительно проверяются в `tests/snapshot.spec.ts`. Набор сценариев покрывает успешную замену и остановку движения, ожидание и блокировку кнопки, пустой ответ/ошибку после успеха, ошибку при демонстрации с продолжающимся движением, карточку при сохранении/снятии выбора, `null` скорости и курса/нейтральный значок, усечение на 100, неизменность настоящей позиции при продвижении `page.clock`, отсутствие смены вида карты при повторной загрузке, отсутствие тела ответа и постоянную подсказку. Тесты блокируют запросы к тайлам. Все пройдены в указанном запуске `npm test`.

В CHECKPOINT-03 указано 10 браузерных тестов на предыдущем этапе. Сейчас `tests/r3-browser.spec.ts` включает сценарии движения и выбора, а тесты R4 добавлены в этот же файл; `tests/example.spec.ts` по-прежнему проверяет выбор и повторный клик. Отдельного списка или git-истории изменений старых тестов в рамках этого ревью не проверялось, поэтому требование «изменены только тесты состояний R2 из B-16» не подтверждаю как факт. Тесты движения и выбора в текущем наборе существуют и зелёные.

### B-20 — финальная приёмка

Автоматические критерии выполнены: тесты, TypeScript и production build прошли. README-команды проверок (`npm test`, `npx tsc --noEmit`, `npm run build`, `npm run lint`) выполнены успешно. `git ls-files` подтверждает, что `.env.local` не отслеживается Git.

Ручная проверка живого источника зафиксирована по сообщению пользователя: с настроенным ключом при запросе судно было получено; без ключа отображалось «Попытка <время> не удалось получить данные: Ключ AISStream не настроен». Таким образом, оба сценария B-20 с ключом/без ключа сообщены как проверенные; время и количество судов для успешной загрузки, а также дата ручной проверки пользователем не предоставлены. Поиск ключа по рабочей копии, `.next/static` и архиву checkpoint не выполнялся; секретное значение не читалось. `.env.local` не отслеживается Git. README также содержит `npm ci` и `npm run dev`; эти установочная и интерактивная команды в данном ревью не запускались.

### B-21 и US-10 — инструкция

`README.md` содержит требования к Node.js/npm и интернету, команды установки, настройки `AISSTREAM_API_KEY` без значения, запуска локального сервера и открытия приложения (`:5-27`); команды проверок перечислены в `:29-36`. Описаны снимок по кнопке, неполнота выборки, сохранение предыдущего набора при ошибке, использование времени из ответа сервера и остановка демодвижения только после непустого успеха (`:38-44`). Ограничения и отсутствие автоматического обновления/истории также перечислены (`:46-53`). Это покрывает содержание инструкции для US-10 и оговорённые требования README по смыслу.

При этом запуск инструкции на чистом/втором ноутбуке не проводился, а команды `npm ci` и `npm run dev` не исполнены в рамках проверки; практическая самостоятельность установки остаётся непроверенной. README намеренно использует формулировки «не мониторинг» и «не все суда района» в оговорках, а не обещает мониторинг или полноту данных; это соответствует смыслу B-21 и текста задания о честном описании выборки.

## Итог

**По проверенной реализации, тестам и содержанию README соответствие B-18, автоматической части B-19, автоматическим пунктам B-20, B-21 и содержанию US-10 подтверждено. Пользователь сообщил о ручном успешном получении судна с ключом и ожидаемом сообщении об отсутствии ключа без него.** Точное время/количество судов для успеха, проверка ключа в перечисленных артефактах и запуск установки на втором/чистом ноутбуке не подтверждены.

**Решение ревью:** автоматические проверки пройдены, ручные сценарии AIS с ключом и без ключа зафиксированы со слов пользователя; доступность AISStream подтверждена для сообщённого успешного запроса. Практическая установка на другом ноутбуке и проверка ключа в рабочей копии, `.next/static` и архиве остаются непроверенными.
