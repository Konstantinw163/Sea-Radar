# CHECKPOINT-01 — B-01…B-07 и US-01…US-04

## Итог ревью

**Решение: принять с оговорками по проверяемости.** По просмотренным файлам реализация соответствует основным функциональным критериям B-01…B-07 и US-01…US-04. Ручная проверка в браузере выполнена пользователем. Проверки сборки, тестов и отдельных критериев, требующих наблюдения в браузере/консоли, в рамках этого ревью не запускались и независимо не подтверждались.

## Запуск

- `npm run dev`
- Приложение настроено на локальный адрес `http://127.0.0.1:3000` для Playwright; приложение не должно открываться наружу.

## Что реализовано и сопоставление с задачами

- **B-01 / US-01:** минимальное приложение Next.js App Router, React и TypeScript с `strict`; скрипты запуска и сборки определены в `package.json`. В зависимостях есть Next.js, React, Leaflet и Playwright Test, стороннего тестового фреймворка не обнаружено в проверенных файлах.
- **B-02 / US-01:** Leaflet импортируется динамически в клиентском компоненте; подключены CSS Leaflet, слой OpenStreetMap Standard с атрибуцией, задан район и начальные координаты/zoom. Контейнер карты занимает доступную высоту и ширину.
- **B-03 / US-02:** определены тип и конфигурация демонстрационного судна; в итоговом состоянии конфигурация содержит три демонстрационных судна. Значки несут `data-vessel-id` и `data-icon`, курс используется для ориентации, предусмотрена нейтральная ветка при `null`. Источник подписан «Демонстрационные данные».
- **B-04 / US-04:** клик по маркеру выбирает судно и открывает карточку; повторный клик не снимает выбор, отдельной кнопки закрытия нет. Поля карточки включают идентификатор, название, координаты, скорость, курс, время и источник; форматирование скорости различает ноль и неизвестное значение. Название выводится React-текстом, не HTML.
- **B-05:** заданы три маршрута литералами, по 10 точек каждый, внутри согласованного района; для судов заданы скорости.
- **B-06 / US-03:** общий интервал 2000 мс обновляет все суда; направление рассчитывается начальным азимутом большого круга. На последней точке скорость устанавливается в `0`, после остановки судно не меняется. Таймеры очищаются при размонтировании; выбранная карточка получает данные из состояния судов.
- **B-07:** конфигурация Playwright задаёт один проект Chromium и поднимает dev-сервер на loopback. Тест блокирует запросы к тайлам, проверяет наличие трёх маркеров, открытие карточки выбранного судна и сохранение карточки после повторного клика.

## Проверки и ограничения результата

- Ручная проверка в браузере: **выполнена пользователем**, по его сообщению соответствует требованиям. Детали и протокол проверки не предоставлены.
- `npm run build`: не запускалась в рамках ревью.
- Playwright Test (результат запуска предоставлен пользователем): `Running 1 test using 1 worker`; тест `tests\\example.spec.ts:3:5 › selects a vessel and keeps its card open on repeated click` прошёл (`1 passed`, 5.1s; сам тест — 911ms).
- Визуальная проверка движения, остановки, изменения размера окна и обновления страницы не повторялась отдельно.
- Проверка накопления интервалов после hot reload и счётчика тиков в консоли не выполнялась отдельно.
- Проверка теста на независимость от сетевых тайлов видна в коде (маршрут запросов блокируется), но сам тест не запускался.
