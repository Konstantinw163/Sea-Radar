# TASK_SPEC — B-11…B-13 (SPRINT-02)

## Цель и границы

Реализовать оставшуюся часть 4: кнопка получает конечный снимок AISStream по согласованным правилам, настоящие суда и их карточки отображаются на существующей карте, подписи и сообщения различают успех, пустой результат и ошибку.

Основа: согласованные значения и порядок из `../tasks/SPRINT-02.md`, разделы «Согласованные значения», B-11…B-13 и «Порядок работы». Образец для преобразователя — `../../data/samples/position-report.sample.json`; его провенанс — `../../data/samples/PROVENANCE.md`. Изменять работу B-08…B-10 только если обнаружится конкретное несоответствие, необходимое для B-11…B-13. Не добавлять непрерывное обновление, историю, паузу/перемотку, новые районы, серверное хранение снимка или новые тестовые фреймворки.

## Исследование и решения

- Реальный образец — первичный источник регистра и фактической структуры. В наблюдённом `PositionReport` `MetaData` содержит `MMSI`, `MMSI_String`, `ShipName`, `latitude`, `longitude`, `time_utc`; позиционные поля внутри `Message.PositionReport` написаны `Latitude` и `Longitude`. Не подменять вложенные координаты координатами `MetaData`: следовать явному маппингу SPRINT-02.
- В образце есть оба представления времени: строка `MetaData.time_utc` с наносекундами и целое `Message.PositionReport.Timestamp`. Для модели использовать именно `MetaData.time_utc`, как предписано SPRINT-02; `Timestamp` не является запасным источником. Преобразовать указанную UTC-строку в ISO 8601 с миллисекундами, не полагаясь на прямой `Date.parse` строки с наносекундами/`+0000 UTC`.
- Внешнее сообщение `SubscriptionConfirmation` — служебное, не позиция. Reader пропускает его и ждёт `MessageType: 'PositionReport'` в пределах исходного 15-секундного окна; таймер не перезапускается после подтверждения. Для сбора B-12 принимать только позиционные сообщения, а не подтверждение.
- Данные снимка — временное состояние одной попытки. Новый запрос создаёт новый сбор и заменяет предыдущий результат в интерфейсе; данные не объединяются между запросами.
- Сохраняются фиксированные тексты, коды ошибок, область, лимит и формат ответа из SPRINT-02. API-ключ остаётся только в серверном процессе и в сообщении подписки к AISStream; браузер получает только результат/фиксированную ошибку.

## Порядок выполнения

### 1. B-11 — преобразователь сообщения в судно

1. Реализовать чистую серверную функцию преобразования одного сырого сообщения `PositionReport` в модель судна или результат «отбросить»; не обращаться к сети, часам или UI внутри преобразователя.
2. Применять согласованный маппинг:
   - `id` ← `String(MetaData.MMSI)`; MMSI обязателен и не может быть пустым;
   - `name` ← `MetaData.ShipName`, обрезать пробелы по краям, пустое значение → `null`;
   - `lat`/`lon` ← `Message.PositionReport.Latitude/Longitude`;
   - `timestamp` ← `MetaData.time_utc`, распарсить UTC-время и нормализовать в ISO с миллисекундами;
   - `speedKnots` ← `Message.PositionReport.Sog`; `courseDeg` ← `Message.PositionReport.Cog`;
   - `source` — `'aisstream'`.
3. Позицию принять только при числовых конечных координатах в диапазонах `lat [-90, 90]`, `lon [-180, 180]`, непустом MMSI и парсящемся timestamp. Значения `91`/`181`, `NaN`, бесконечность, отсутствующие координаты, невалидное время или MMSI отбрасывают всё сообщение; не создавать позицию `0,0` по умолчанию.
4. Необязательные поля валидировать отдельно: скорость вне `[0, 102.2]`, включая `102.3`, отсутствующая или нечисловая → `null`; курс вне `[0, 360)`, включая `360`, отсутствующий или нечисловой → `null`. Невалидная скорость/курс не отбрасывают позицию. Ноль скорости остаётся числом `0`.
5. Вручную сверить с сохранённым образцом как минимум `id` по MMSI, координаты по вложенному `Message.PositionReport` и скорость/курс по `Sog`/`Cog`. Отдельно проверить, что испорченные обязательные координаты/время не создают судно, а ноль скорости не превращается в `null`.

### 2. B-12 — сборщик снимка и окончательная форма endpoint

1. Обернуть WebSocket reader в сборщик с заменяемым источником событий и управляемыми часами/таймерами. Начало 15 секунд — начало серверной обработки запроса, включая соединение и отправку подписки. Фильтровать служебное подтверждение подписки, продолжать слушать до позиции, ошибки или конца окна.
2. Принимать только преобразованные валидные позиции. Хранить максимум 100 уникальных судов по `id`:
   - первое валидное сообщение создаёт судно;
   - более новая `timestamp` для того же `id` целиком заменяет объект;
   - при равном времени оставить принятую первой позицию;
   - более старое сообщение не заменяет новое;
   - повторные сообщения одного MMSI не увеличивают количество уникальных судов и сами по себе не завершают сбор.
3. По достижении 100-го уникального валидного судна немедленно завершить сбор с `reason: 'limit_reached'`, `truncated: true`; иначе при живом соединении завершить по истечении окна с `reason: 'window_elapsed'`. Пустой набор по истечении окна — успешный ответ с `vessels: []`, `count: 0`, не ошибка.
4. Любая ошибка провайдера, разрыв после подписки или отмена запроса приводит к ошибке всей попытки; уже накопленный частичный набор не возвращать как успех. Ошибки до открытия/отправки подписки классифицировать `connect_failed`; фиксированные коды и русские сообщения брать из SPRINT-02, сырой текст источника наружу не выдавать.
5. Завершать попытку только один раз; во всех исходах очищать окно/таймеры, обработчики и WebSocket. Поздние события после завершения игнорировать. Состояние и коллекция принадлежат только одной попытке; повторный запрос не использует данные предыдущего.
6. Финальный успешный ответ `GET /api/snapshot`: `{ ok: true, vessels, collectedAt, windowSeconds, count, truncated, reason }`; `count` равен числу уникальных судов. Ошибка — HTTP 502 `{ ok: false, attemptedAt, error: { code, message } }` с согласованным кодом и фиксированным текстом. `attemptedAt` и `collectedAt` формировать по переданным часам, где это требуется контрактом.
7. Проверить сценарии отдельными управляемыми событиями/временем, не подключаясь к сети: окно с позициями и пустое окно; лимит 100 уникальных судов; повтор MMSI и новое/старое/равное время; невалидная позиция; ошибка источника после части позиций; разрыв; отмена; проверка закрытия ресурсов и однократного результата. Эти проверки правил сбора выполнить вручную на данном этапе; автоматизацию правил сбора оставить для R3.

### 3. B-13 — кнопка, карта, подписи и сообщения

1. В существующем клиентском компоненте карты переиспользовать маркеры, значки и карточку. Ввести общую модель отображения с nullable name/speed/course и отдельные данные маршрута только для демонстрационных судов; не заставлять реальные AIS-суда иметь демонстрационные `route`, `routeIndex` или `stopped`.
2. В idle-demo показывать три прежних демонстрационных судна, их движение, карточки и подпись «Демонстрационные данные». При нажатии «Загрузить настоящие позиции»:
   - перейти в `loading`, остановить демонстрационный таймер, удалить демонстрационные маркеры, выбор и карточку;
   - оставить базовую карту, показать «Загрузка…», заблокировать кнопку и отправить ровно один запрос;
   - не запускать параллельную попытку при повторном нажатии.
3. Успех заменяет содержимое карты набором ответа; реальные суда между запросами не двигаются. Успешная подпись дословно: `AISStream · снимок за 15 с · получен HH:MM:SS UTC · судов: N · выборка неполная`; при `truncated` добавить ` · остановлено на лимите 100`. «15» — фиксированная длительность окна из конфигурации. При первом непустом успехе вернуть карту к начальному центру/zoom; последующие результаты не меняют пользовательский вид карты.
4. При пустом успехе оставить на карте ноль судов, показать подпись с `судов: 0` и сообщение «За время сбора позиции не получены». Не писать «судов нет».
5. При ошибке убрать все суда, выбор и карточку; подпись — «Данных на карте нет», сообщение — «Не удалось получить данные: <message>» с фиксированным текстом из error response. Учебные суда возвращаются только после обновления страницы. Не сохранять предыдущий успешный снимок при ошибке.
6. При выборе реального судна открывать ту же карточку, что и для демо: ID, название как текст, координаты `toFixed(5)`, скорость с теми же правилами (включая `0 уз` и `null` → «Нет данных»), курс, `HH:MM:SS UTC`, источник «AISStream». `null` курс использует нейтральный значок. Повторный клик по выбранному судну карточку не закрывает.
7. Проверить в браузере один MMSI из ответа: соответствующий маркер, его выбор и совпадение значений карточки. Проверить no-key ошибку и пустой успех как разные состояния; блокировать тайлы в Playwright. Существующие тесты B-07 должны остаться зелёными; новые браузерные проверки использовать только Playwright Test и один браузер.
8. На review проверить: ключ отсутствует в клиентском bundle и ответе; подпись всегда называет выборку неполной; исчезновение судна в следующем снимке не трактуется как уход из района; между снимками реальные суда неподвижны.

## Критерии завершения

- **B-11:** преобразователь сверяет требуемые поля с live sample; координаты/время/MMSI валидируются; невалидная позиция не отображается; nullable speed/course и ноль различаются.
- **B-12:** контракт 15 секунд/100 уникальных судов и все исходы реализованы; финальная форма ответа и ошибки совпадают с SPRINT-02; повторная попытка изолирована от предыдущей.
- **B-13:** кнопка и все состояния `idle-demo`, `loading`, `success`, `empty`, `error` соответствуют текстам и поведению выше; одно настоящее судно сопоставлено с маркером и карточкой; без ключа демонстрация при старте работает.
